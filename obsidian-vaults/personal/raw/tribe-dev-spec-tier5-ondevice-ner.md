# Tribe Dev Spec — Tier 5: On-Device NER

## Overview

Tier 5 is the most sophisticated tier: a fully on-device Named Entity Recognition (NER) model that extracts WHAT (activity), WHEN (temporal expression), and WHERE (location entity) from the user's prompt with sequence-level understanding. Unlike Tier 4's pattern matching, NER understands context and handles ambiguity. Unlike Tier 1 (Claude API), it runs entirely offline with no cost per inference.

This tier is suitable for production deployment once the model is trained and validated, and represents the ideal balance of intelligence, privacy, and cost.

---

## Requirements

### Functional Requirements
- Extract named entities from prompt: `ACTIVITY`, `TIME`, `LOCATION`
- Return entity spans with confidence scores
- Support English and Hungarian (requires separate model or multilingual model)
- Provide actionable nudge for each missing entity type
- Minimum prompt length: 5 characters
- Debounce: 500ms (fast enough for near-real-time feedback)

### Non-Functional Requirements
- Model size: < 15 MB (after quantization)
- Inference latency: < 150ms on Snapdragon 720G equivalent
- Works fully offline
- Memory footprint: < 50 MB at runtime
- Privacy: no prompt data leaves the device

## Architecture

```
UserPromptInput
    ↓ (debounced 500ms)
NERService
    ├── Tokenizer (on-device, BPE/WordPiece)
    ├── NERModel (TFLite / ONNX)
    │     → entity spans: [{text, label, confidence}]
    └── NudgeMapper
            → NudgeBanner message
```

### NERService

```typescript
interface EntitySpan {
  text: string;
  label: 'ACTIVITY' | 'TIME' | 'LOCATION';
  startChar: number;
  endChar: number;
  confidence: number;
}

interface NERResult {
  entities: EntitySpan[];
  hasActivity: boolean;
  hasTime: boolean;
  hasLocation: boolean;
  missingDimensions: ('activity' | 'time' | 'location')[];
}

async function extractEntities(prompt: string): Promise<NERResult>
```

### Model Architecture

- Base: DistilBERT (multilingual) — `distilbert-base-multilingual-cased`
- Fine-tuned on: custom NER dataset with `ACTIVITY`, `TIME`, `LOCATION` labels
- Quantization: INT8 post-training quantization (reduces model ~4x)
- Runtime: TensorFlow Lite (React Native via `react-native-tflite` or equivalent)

### Tokenizer

- WordPiece tokenizer (same vocabulary as DistilBERT multilingual)
- Max sequence length: 64 tokens (truncate if longer)
- Tokenizer runs on-device (serialized vocabulary file bundled with app)

## Training Data

### Dataset Composition
- 10,000+ labeled prompt examples
- Labels: `B-ACTIVITY`, `I-ACTIVITY`, `B-TIME`, `I-TIME`, `B-LOCATION`, `I-LOCATION`, `O`
- Sources:
  - Bootstrapped using Claude API (Tier 1) on real user prompts (anonymized)
  - Augmented with synthetic examples generated by GPT-4
  - 70% English, 30% Hungarian (to match expected user distribution)

### Labeling Format (BIO scheme)
```
I    O
want O
to   O
swim B-ACTIVITY
at   O
Palatinus B-LOCATION
on   O
Saturday  B-TIME
afternoon I-TIME
```

### Validation Metrics (minimum thresholds)
| Entity | F1 Score |
|--------|----------|
| ACTIVITY | ≥ 0.88 |
| TIME | ≥ 0.85 |
| LOCATION | ≥ 0.82 |
| Macro avg | ≥ 0.85 |

## Model Training Pipeline

1. **Data collection**: Gather anonymized prompt examples from Tier 1 logs + synthetic generation
2. **Annotation**: Apply BIO labeling (Claude-assisted + human review for sample)
3. **Training environment**: Python, HuggingFace Transformers, PyTorch
4. **Fine-tuning**: DistilBERT multilingual + token classification head (7 labels: B/I for each + O)
5. **Evaluation**: Hold-out test set (20%), per-entity F1, confusion matrix
6. **Export**: `model.save_pretrained()` → ONNX export → TFLite conversion
7. **Quantization**: INT8 post-training quantization
8. **Bundling**: Copy `.tflite` + tokenizer vocab to `assets/models/`
9. **Versioning**: `ner_model_v{N}.tflite` — OTA update capability

### Training Script (abbreviated)
```python
from transformers import (
    AutoTokenizer,
    AutoModelForTokenClassification,
    TrainingArguments,
    Trainer,
    DataCollatorForTokenClassification,
)

model = AutoModelForTokenClassification.from_pretrained(
    "distilbert-base-multilingual-cased",
    num_labels=7,  # B-ACT, I-ACT, B-TIME, I-TIME, B-LOC, I-LOC, O
)
```

## NudgeMapper

Maps NERResult to user-facing nudge messages (same message templates as Tier 3/4):

```typescript
function getNudgeMessage(result: NERResult, locale: 'en' | 'hu'): string | null {
  const missing = result.missingDimensions;
  if (missing.length === 0) return null;

  const key = missing.sort().join('_');  // e.g. 'location', 'time_location'
  return NUDGE_MESSAGES[locale][key] ?? NUDGE_MESSAGES[locale].missingAll;
}
```

## Testing

### Unit Tests
- `NERService.extractEntities()` — 50 labeled examples, verify entity spans and labels
- `NudgeMapper.getNudgeMessage()` — all missing dimension combinations, both locales
- Tokenizer — verify BPE encoding matches training-time tokenization

### Integration Tests
- Model loads within 3 seconds of app startup
- Inference completes within 150ms for 50-char prompt
- Full pipeline: TextInput → NERResult → NudgeBanner update
- Fallback: if model fails to load → Tier 2 static guide activates

### UI Behavior Tests (User Flow Scenarios)
1. "I want to swim at Palatinus on Saturday afternoon" → no nudge (all 3 entities detected)
2. "I wanna go squashing" → nudge: WHEN + WHERE missing
3. "Going hiking on Sunday" → nudge: WHERE missing
4. "Meeting in Budapest" → nudge: WHEN missing + ACTIVITY somewhat ambiguous
5. Hungarian: "Úszni szeretnék szombat délután a Palatinuson" → no nudge
6. App launches with model → cold start inference within 150ms (warm) and 500ms (cold)

## Open Questions

- Should we ship a single multilingual model or two separate EN/HU models? (Tradeoff: quality vs. bundle size)
- How do we handle entity boundaries for compound Hungarian expressions (agglutinative morphology complicates BIO tagging)?
- Should entity highlighting be enabled by default or opt-in (possible distraction during typing)?
- How do we update the model OTA without a full app store release?
- What is the minimum device spec we need to support? (Defines quantization aggressiveness)
- Should we collect anonymized inference results to improve the model iteratively?
- How do we handle the case where the user intentionally writes a vague prompt (e.g., "looking for something fun")?
