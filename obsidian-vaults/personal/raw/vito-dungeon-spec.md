# Create a SPECIFICATION.md based on @SPECIFICATION.template.md for a Web Browser based Medieval-style RPG story generator

## Goals
- Make a SPECIFICATION.md that a Planner Agent can use to lay out a detailed implementation plan for Worker agents.
- Refer to the provided template, but use your best-suited agents to override layout, if a better outcome is predicted.
- The application to be implemented is a Medieval-style RPG story generator web browser app, that generates a paragraph in a story and offers 2-4 options to choose from what to do next. Then the selected option shapes the next generated paragraph with the next options. Do a web search on *Fighting Fantasy* books and *Diablo 1* (by Blizzard Entertainment) UI to get inspiration for the game mechanics and UI design.
- The app should be Titled *Vito's Dungeon* on UI.
- Add instructions for Planner to include required environment variables along with a quick guide on how to get those variables and why.
- Key features listed here are the MINIMUM to implement, but do web search to look for areas to improve and new fun game mechanics.
- Look for knowledge gaps and logical ambiguities, and run parallel subagents to find out the best fitting ideas to resolve the issues. Do NOT ask for user for input, decide on best idea by a judge agent.
- Unit tests and Integration tests are NOT enough, UI behavior MUST also be verified by user flow scenarios.

## Architecture
**Backend**: Django  
**Frontend**: React  
**Database**: PostGreSQL for embedded vectors and other persisted entities  
**Deployment**: The application should be deployed in a self-contained Docker container system that will be added to an existing network.

## Key features to implement
- User authentication and profile management
- Story generation using a language model API (e.g., OpenAI GPT-4). The story should be generated in a way that allows for branching narratives based on user choices.
- Interactive UI that displays the generated story and presents options for the user to choose from.
- State management to keep track of the user's progress through the story and their choices.
- Integration with a vector database to store and retrieve (RAG) story elements, user choices, and other relevant data for personalized story generation.
- Character and inventory management system to enhance the RPG experience. This could include tracking the player's health, items, and other stats that influence the story.
- Dynamic story generation that adapts to the user's choices and character stats, creating a uniquely challenging narrative experience for each player.
- LLM-generated events and monsters that the player can encounter, with descriptions and stats that influence the story and gameplay. The monster and event templates should be deterministic, but the content should be generated by the language model based on the current story context and player stats.
- Fully deterministic combat system that allows players to engage in battles with monsters. The combat outcomes should be determined by a combination of player stats, monster stats, and random chance, but the mechanics and rules should be consistent and predictable.
- NPC interactions where the player can meet and interact with non-player characters that can provide quests, information, or items. The NPCs should have their own personalities and storylines that can influence the main narrative. NPC models are also deterministic templates with LLM-generated content.
- Save and load game functionality to allow users to continue their adventure at a later time.
- Diablo 1 style UI with a medieval theme to enhance immersion. These should be static assets that are stored in the frontend and not generated by the language model. Do a web search in Pinterest and other image platforms for scraping background images, UI design elements, and layout.
- Language selection for story generation to allow users to experience the game in different languages. Only English and Hungarian are required, but more can be added if feasible.
- Only story text should be generated by the language model in the selected language, all UI elements should be static assets stored in the frontend. Do a web search to find out what are the best practices for this kind of implementation.
- LLM model selection at the beginning of each game session to allow users to choose which language model they want to use for story generation. This could include options for different providers (e.g., OpenAI, Anthropic, Google, Ollama etc.) and different model sizes (e.g., GPT-3.5, GPT-4, etc.). Each model provider's API key should be stored in environment variables, and the app should be able to switch between them based on user selection.
